# Pavlusha 0.8.0 — подготовка

Эта версия развивает опубликованную 0.7.0; сам по себе номер версии не означает,
что релиз опубликован. История предыдущего выпуска — в [release-0.7.0.md](release-0.7.0.md).

## Изменения

- Запуск модульной сборки объединён в один JSON с настройками `runtime` и списком
  `modules`. Примеры для Qwen, Ornith и Liquid требуют указать пути к модели и
  серверу. Каталоги работы и сессии задаются отдельно.
- Добавлены экспериментальные адаптер Perplexity Agent API и оркестрация: главный
  агент может передать задачу локальному Павлуше и получить его файлы. Доступен и
  отдельный режим локальных агентов с сохранением KV-кэша. Требования и ограничения
  описаны в [orchestration.md](orchestration.md) и
  [perplexity-agent-adapter.md](perplexity-agent-adapter.md).
- Добавлены модуль завершения для небольших сборок и варианты сохранения последних
  сообщений при сбросе контекста. Project State поддерживает экспериментальный
  совместный review с обновлением состояния и handoff.
- Детектор повторов получил настройки окна рассуждений, сообщения с результатом
  повторного действия и сокращение повторяющихся ходов в контексте.
- Зависимости модулей объединены в `requirements.txt`; тестовые зависимости
  устанавливаются через `requirements-test.txt`.

## Ограничения

Модули — доверенный Python-код. Browser и Expert требуют отдельной настройки.
Оркестрация требует графического терминала; профиль Perplexity также требует API-ключа
и отдельного локального сервера. Внешний API может тарифицироваться, а автоматического
лимита расходов нет. Результаты отдельных догфудов не гарантируют надёжность при любых
ошибках или нагрузке. Совместимость со старыми сессиями и конфигами не гарантируется.

`shell_released` не обеспечивает прежнюю обязательную последовательность review и
сброса. Между технической сессией и состоянием модулей нет общей crash-safe транзакции;
неизвестный результат прерванного действия блокирует автоматический повтор.
