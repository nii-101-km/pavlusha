# Браузер для Павлуши 0.9.1

Для визуальной работы с веб-страницей Павлуша использует модуль **GUI**: он открывает отдельный браузер на собственном виртуальном экране и получает снимки экрана. Обычный браузер пользователя при этом не выбирается автоматически. Модуль **Browser** — отдельный необязательный инструмент диагностики уже выбранной страницы; для обычной визуальной проверки он не нужен.

## 1. Подготовка

Нужны Linux, Python и окружение проекта из [README](../README.md), а также `bubblewrap` и работающие пользовательские пространства имён. Для GUI нужны Xvfb, X11 и Python-пакеты из `requirements.txt`. Для браузера-помощника нужны Epiphany, D-Bus и GSettings. Например, в Debian/Ubuntu пакеты можно установить так:

```sh
sudo apt-get install bubblewrap xvfb epiphany-browser dbus-daemon libglib2.0-bin
```

Названия пакетов в других дистрибутивах могут отличаться. Из каталога Павлуши запустите проверку:

```sh
./check-browser.sh
```

Скрипт использует активное окружение или `.venv` проекта; для другого окружения задайте `PAVLUSHA_VENV`. Он проверит компоненты, запустит изолированный браузер с локальной тестовой страницей и сообщит результат. Внешняя сеть и модель не используются. Если чего-то не хватает, скрипт подскажет, что установить; сам он ничего не устанавливает. Проверка не определяет, поддерживает ли модель изображения.

Для понимания снимков экрана модель и сервер должны принимать изображения. Для совместимой мультимодальной GGUF-модели настройте подходящий `--mmproj`; конкретные параметры зависят от модели и сервера.

## 2. Подключение GUI

Добавьте в массив `modules` конфигурации сборки (в профиле `examples/qwen.native.config.json` это уже есть):

```json
{"factory": "pavlusha_modules.gui:create_extension"}
```

По умолчанию `allow_network` равен `false`. Сборка запускается через `project_state_agent.py` с конфигурацией, рабочим каталогом и отдельным каталогом сессии, как в [README](../README.md). Если GUI-модуль включён, но отсутствуют Xvfb или Python-зависимости, запуск сборки завершится ошибкой: установите зависимости или уберите модуль из конфигурации.

Попросите Павлушу, например: «Запусти локальное приложение из рабочего каталога и проверь его интерфейс в браузере. Не используй внешнюю сеть». Его `gui_start` запускает программу в `/work`; успешные действия дают снимок, а `view_gui` делает новый. Приватный экран по умолчанию имеет размер 800×600. Это не то же самое, что открыть страницу пользователю в обычном браузере. Чтобы модель могла оценивать снимки, нужна поддержка изображений.

## 3. Локальный сайт без внешней сети

При `network: false` у GUI собственная изолированная сеть. Сервер, отдельно запущенный через shell или `process_start`, находится в другом окружении и по своему `127.0.0.1` из браузера GUI недоступен. Запустите сервер **и** браузер одной командой `gui_start`, чтобы они разделяли один локальный интерфейс. Пример для статических файлов рабочего каталога, в формате действия текущей сборки:

```json
{"action":"gui_start","command":"python3 -u -m http.server 8000 --bind 127.0.0.1 > /tmp/site.log 2>&1 & exec pavlusha-browser http://127.0.0.1:8000/","network":false,"delay":8}
```

Для другого приложения замените серверную команду и порт на подходящие ему. Браузер остаётся основным процессом; сервер в той же среде будет закрыт вместе с GUI. Для следующего снимка используйте `{"action":"view_gui","delay":1}`, для завершения — `{"action":"gui_close"}`. Эти действия обычно выбирает сам Павлуша в ответ на обычное задание.

Если нужно открыть сервер, уже работающий в сетевом пространстве компьютера, GUI можно отдельно разрешить `network: true` через `settings: {"allow_network": true}` и запросить `network: true` при `gui_start`. Это предоставляет доступ к **сети компьютера в целом**, а не только к localhost; настройка процессов и обычного shell независима. Для локальной проверки предпочтителен вариант выше.

## 4. Если не открывается

- `GUI toolkit requires Xvfb` или ошибка про `python-xlib`/Pillow: проверьте системные пакеты и активированное Python-окружение.
- `pavlusha-browser: missing ...`: установите перечисленный в ошибке пакет. Помощник использует фиксированные системные пути, а не автоматически выбранный пользовательский браузер.
- `network_not_granted`: запуск запросил сеть, но модулю GUI она не разрешена. Для локального приложения запустите сервер и браузер вместе с `network: false`.
- Пустая страница или ошибка соединения: проверьте команду, порт и `/tmp/site.log` **в той же GUI-среде**. В отдельной shell-среде свой `/tmp` и своё сетевое пространство. Проверьте, что сервер не завершился до старта браузера.
- `gui_start` сообщает об успешном запуске, но это ещё не подтверждает правильность страницы: посмотрите снимок и проверьте нужные элементы и действия.

## 5. Необязательная диагностика через Browser

Модуль `pavlusha_modules.browser:create_extension` без `settings.config` находится в пассивном состоянии. Это отдельный механизм для диагностики выбранной страницы через доверенный адаптер, а не способ запустить приватный GUI-браузер. CDP-адаптер подключается только к loopback-адресу и требует ровно одну вкладку с указанным `target_id` **или точным** `target_url`. Выполнение JavaScript по умолчанию выключено; `allow_evaluate: true` позволяет выполнять код со стороны страницы и может менять её состояние. Не включайте его без необходимости.

Для возобновления сессии используйте ту же конфигурацию модулей и сохраните рабочий и технический каталоги. Сама GUI-сессия после перезапуска не восстанавливается: страницу потребуется открыть заново.
