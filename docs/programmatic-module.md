# Экспериментальное программное выполнение

Модуль `pavlusha_modules.programmatic:create_extension` позволяет Павлуше запускать ограниченную по времени Python-программу в обычной песочнице `/work`. Программа может вызывать разрешённые инструменты модулей через локальный канал, пока выполняется `execute_program`. Это отдельный модуль: Project State и Token Window не нужны.

Пример конфигурации:

```json
{
  "factory": "pavlusha_modules.programmatic:create_extension",
  "settings": {
    "allowed_tools": ["shell", "odt_inspect"],
    "timeout_seconds": 60,
    "max_calls": 20,
    "output_limit": 8000
  }
}
```

Другие модули, в том числе Shell или Office, подключаются отдельно. По умолчанию `allowed_tools` пуст. Программа может вызывать только инструменты, которые одновременно:

1. перечислены в `allowed_tools`;
2. подключены и доступны модели в снимке текущего хода, включая ограничения exclusive-режима;
3. явно объявлены своим владельцем с `Tool(..., programmatic=True)`.

Сейчас на программный вызов рассчитаны `shell` из модуля Shell, операции Office, `browser_diagnostics`, а также `delegate_agent` и `collect_agent` из модуля оркестрации. Владелец другого модуля может явно разрешить свой инструмент, если тот возвращает только `Outcome.result` и не требует управления моделью, `controls` или `observations`. `finish`, интерактивная пауза и сам `execute_program` недоступны. Инструменты, требующие освобождения модели, также не поддерживаются. Выбор проверяется при каждом вызове и не меняет доступность инструментов для модели.

Пример программы, которую модель может передать в `execute_program`:

```python
from pavlusha_tools import call

result = call('shell', command='printf hello')
print(result['stdout'])
```

`call` возвращает словарь результата или вызывает исключение при ошибке. Аргументы проверяются той же схемой, что и обычный вызов инструмента. Инструменты исполняются последовательно в родительской сессии; канал существует только во время выполнения программы. Результат программы — код завершения, ограниченный вывод и число вызовов. Отдельные вызовы и результаты фиксируются в техническом журнале; в историю модели попадает итог `execute_program`.

## Обычный файл сценария в проекте

Сценарий можно сохранить как обычный `.py` в рабочей папке и перенести вместе с
проектом. Специальный формат и метаданные не требуются; комментарии с назначением
и зависимостями необязательны. Например, если в `/work/check_project.py` лежит
нужный код, его можно исполнить в другой сессии, передав в `execute_program`:

```python
exec(compile(open('/work/check_project.py', encoding='utf-8').read(),
             '/work/check_project.py', 'exec'))
```

Такой код запускается внутри того же программного модуля: вызовы `call(...)`
подчиняются allowlist, схемам инструментов и ограничениям модуля. Права самих
разрешённых инструментов остаются отдельным вопросом. Обычный запуск файла
пользователем через системный Python имеет права пользователя и не проходит
через эти ограничения. Расширение `.py` само по себе не задаёт прав.

В сквозном локальном тесте файл был создан через `shell` в одной сессии и
прочитан приведённым способом в новой: разрешённый вызов `shell` выполнился,
вызов отсутствующего в allowlist инструмента был отклонён. Журнал новой сессии
содержал переданный в `execute_program` код-обёртку и отдельные записи начала и
завершения разрешённого вызова. Отказ на этапе allowlist **не создаёт отдельную
запись вложенного вызова**; в этом тесте он попал в результат, потому что
сценарий напечатал ошибку. Обёртка читает актуальное содержимое файла при запуске:
ядро не создаёт версионированный снимок файла и не гарантирует запись содержимого
сценария в журнал. Для воспроизводимости храните и проверяйте файл отдельно.

## Границы и восстановление

- Вызов программы является одним действием ядра. До его завершения оно сохраняется как `pending`; при аварии с неопределённым результатом штатное восстановление откажется автоматически повторять действие. Уже выполненные внешние действия не откатываются.
- Срок `timeout_seconds` ограничивает работу самой программы и ожидание между вызовами, но **не прерывает уже выполняющийся инструмент**. Например, запущенная через `shell` команда завершится по собственному ограничению. Если инструмент завис, общий срок не является жёсткой гарантией остановки.
- При достижении лимита вывода или времени программа завершается, но последствия выполненных инструментов сохраняются. Ошибка инструмента также может означать, что его побочные эффекты уже произошли.
- Исходный код и вызовы пишутся в технический журнал. Не помещайте секреты в аргументы. Песочница программы работает без сети и с доступом к `/work`, но разрешённый инструмент может иметь собственные полномочия и побочные эффекты. Например, `shell` может включить сеть, только если она разрешена конфигурацией Shell.
- Это не полная гарантия изоляции: доверенные модули исполняются с правами контроллера. Например, разрешённые операции Calc запускают LibreOffice вне песочницы; их файловые и сетевые полномочия не определяются ограничениями Python-программы. Выдавайте `allowed_tools` только после проверки конкретных инструментов и их настроек.
- Канал и программа существуют в рамках одного вызова; это не долговременный фоновый режим. Вызовы не выполняются параллельно и не переживают завершение сессии. Пользовательский ввод во время выполнения обрабатывается на штатной безопасной границе после возврата инструмента.

Модули являются доверенным кодом: `programmatic=True` — обещание владельца, что инструмент подходит этому контракту. Если такой инструмент вопреки контракту вернёт управление сессией или наблюдения, вызов вернёт ошибку; уже произошедшие побочные эффекты не откатываются. Не помечайте таким образом произвольные инструменты без проверки.

## Последовательная оркестрация

Чтобы программа могла делегировать задачу и забрать файлы, подключите модуль оркестрации отдельно и явно укажите `"allowed_tools": ["delegate_agent", "collect_agent"]` в настройках программного модуля. Оба инструмента по умолчанию скрыты. Пример программы:

```python
from pavlusha_tools import call

child = call('delegate_agent', task='Создай файл result.txt', inputs=[])
if child['status'] == 'finished':
    call('collect_agent', child_id=child['child_id'], paths=['result.txt'])
print(child['summary'])
```

Программа ждёт завершения каждого дочернего агента. Дочерняя рабочая папка отдельная; перенос файлов выполняется через `collect_agent`. Это не фоновые агенты и не параллельные LLM-сессии. Существующие требования оркестрации к графическому терминалу, серверу и KV сохраняются: см. [orchestration.md](orchestration.md).

Время ожидания дочернего агента входит в срок программы, но само делегирование нельзя безопасно оборвать тайм-аутом программы: сначала ожидается подтверждённое завершение ребёнка. Если к этому моменту срок программы прошёл, программа может быть остановлена сразу после возврата инструмента. Подбирайте `timeout_seconds` с запасом, учитывая ограничение 300 секунд. Если завершение ребёнка не подтверждено, сессия останавливается с незавершённым действием и не воспроизводит его автоматически. Результат и возможные побочные эффекты следует проверить вручную.


Для пользовательских скриптов, которым достаточно запускать обычные сессии Павлуши, отдельный запускатель сценариев не нужен. Модель можно оставить работающей между запусками с помощью [`--keep-server`](persistent-server.md).
