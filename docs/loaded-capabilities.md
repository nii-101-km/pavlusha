# Возможности, подключённые через загрузчик

Состав приложения — `examples/state-map.modules.json`. Все фабрики создаёт
`pavlusha_modules.loader`, включая Shell. Это доверенные модули Python. Новый
контракт находится в `event-interface.md`. Произвольный пользовательский
FunctionRegistry и мост истории не возвращены.

Установить зависимости контроллера: `python -m pip install -r requirements-modules.txt`.
Для GUI нужны также Xvfb и системные X11-библиотеки; для рендеринга DOCX/XLSX —
LibreOffice, Poppler и шрифты. Эти внешние зависимости проверяются по месту.

| Модуль | Доступные возможности |
| --- | --- |
| shell | Обычная команда в песочнице; разрешение сети задаётся CLI. |
| project_state | План, review/handoff, восстановление и finish. |
| project_map | Снимок Python-кода при запуске и смене эпохи. |
| images | view_image — PNG/JPEG/WebP; наблюдение через интерфейс ядра. |
| processes | Запуск/статус/логи/остановка фонового процесса в песочнице. |
| gui | Приватный X11-дисплей, ввод, мышь, скриншоты, очистка ресурсов. |
| browser | Диагностика и при отдельном разрешении JS выбранной страницы. |
| expert | Консультация отдельной модели через заданный endpoint. |
| office | DOCX и XLSX: inspect/read/edit/render с прежними ограничениями. |
| gpu_shell | shell_released — временно выгружает Worker для команды в песочнице. |
| reasoning_code | Запись текущего или сохранённого блока рассуждения в /work. |
| loop_detection | Повторы рассуждения и циклы одинаковых действий/результатов. |
| interactive | ask_user — пауза и возобновление с ответом пользователя. |

Модуль Browser без `settings.config` и Expert без настроек загружаются в пассивном
состоянии: соответствующие функции не рекламируются. Для настоящего браузера
укажите файл конфигурации адаптера в `settings.config`; исполнение JavaScript
требует `allow_evaluate` в его конфигурации. Для Expert задайте `base_url`, `model`
и при необходимости `api_key_env`, `allow_network`, `max_calls`, `timeout`.
Адреса и ключи не подставляются автоматически. Сеть процессов и GUI — независимые
`settings.allow_network`, по умолчанию false; сеть экспертного API — тоже отдельно.
Обычный shell и shell_released используют CLI `--network`.

При отсутствии lxml/openpyxl Office сообщает об отсутствии зависимости и не
предлагает соответствующие функции. Рендер — отдельная файловая операция, успешный
рендер не заменяет визуальный просмотр страниц. Инструменты Office основаны на
прежних фиксированных реализациях, изолированных по экземплярам: это не общий
загрузчик пользовательских функций.

LoopDetection использует сохранённый детектор: при подтверждённом повторе рассуждения
запрашивает interrupt и сообщает модели изменить подход. После заданного числа
последовательных прерываний (по умолчанию двух) останавливает запуск. При повторе
цикла действий выводит предупреждение. Выход зависит от поведения модели; гарантия
семантического обнаружения всех петель не заявляется.

Кодовые block_ref ограничены по объёму и количеству, публикуются с номером тюрна,
живут только в одной эпохе и очищаются при reset/restart. Запись происходит в
песочнице, режим create не перезаписывает существующий файл.

shell_released использует политику release_model ядра и существующую супервизию
песочницы, но пока **не принуждает к предварительному review State и не делает
холодный checkpoint/reset после выполнения**, как прежний специализированный
путь. Для этого в текущем интерфейсе нет общего безопасного согласования перед
вызовом инструмента. Самостоятельного сервиса загрузки Transformers нет: команда
запускается в песочнице, и ей необходимы установленные зависимости/модель.
Работа с внешним GPU-сервисом и его уборка не гарантируются shell_released.

Интерактивная пауза и ввод подключены через интерфейс ядра; клавиши и порядок работы
описаны в `event-interface.md`. Потоковое `message` пользователю и ручное
редактирование/сокращение истории не перенесены: интерфейс не предоставляет
независимого канала показа сообщений или управления историей.
Во время exclusive review другие инструменты, включая ask_user, скрыты.
Механизм возражения перед finish, общие события ошибок и аварийные транзакции
остаются отложенными по прежней договорённости.

При терминальном вводе и при `--live` экспериментальная сборка показывает ход работы
в оформлении обычного Павлуши: рассуждение, тюрны, действия и результаты. Для старого
машинного формата вывода используйте `--live --live-format json`; диагностический
`generation.jsonl` сохраняется в обоих форматах. Библиотека Rich входит в
`requirements-modules.txt`; без неё доступно простое текстовое оформление.

## Исторические проверки экспериментальной копии

Актуальный повторный прогон описан в [заметках о выпуске](release-0.7.0.md).

`tests/test_loaded_capabilities.py` проверяет загрузку всей сборки, review/reset,
реальные локальные PNG, DOCX/XLSX, фоновые процессы и GUI в песочнице, запись
кода и ссылки, разрешения, pause/resume, обнаружение петель и release/restore с
управляемым провайдером. Браузер дополнительно проверен с настоящим локальным Chrome
for Testing 156: через загрузчик и Runtime выполнены изменение и чтение DOM,
получена ошибка консоли и проверено освобождение подключения. Тюрны задавал
управляемый провайдер; реальная модель в этом прогоне не участвовала. Эксперт в
этом наборе проверяется контролируемым объектом. DOCX и XLSX отдельно успешно рендерились LibreOffice/Poppler в
PDF и PNG; визуальная проверка полученных страниц не выполнялась.

Полный набор: 135 тестов, 2 пропуска. Также Qwen3.8-27B в отдельном локальном
llama-server выполнила обычную задачу при загрузке всех модулей за 7 тюрнов,
с одним review и сбросом контекста. В отдельном прогоне она выбрала
`shell_released`, сервер выгрузил и заново загрузил модель, после чего модель
завершила задачу за 4 тюрна. Команда в этом прогоне была `printf`, CUDA/Transformers
внутри неё не проверялись. Заданный вызов независимо проверил смену PID сервера.

В последующем отдельном догфуде локальная EmbeddingGemma 2 выполнила задачу на
CUDA через `shell_released` после выгрузки Worker, с сохранением и восстановлением
KV в оперативной памяти. Подробности и границы проверки описаны в `kv-storage.md`.

Первый прогон с `shell_released` не удался: модель повторяла обычный shell, несмотря
на предупреждения, и был прерван. Уточнение инструкции модуля помогло во втором
прогоне; два прогона не доказывают надёжности выбора действия в общем случае.
Исторические журналы этих прогонов находятся в экспериментальной копии и не входят в репозиторий.

После ревью исправлены обработка структурированных ошибок Office в детекторе
повторов и сравнение длительности `shell_released`. Добавлены проверки продолжения
полной сессии после ошибок DOCX/XLSX, циклов обоих shell-инструментов и отсутствия
ложного обнаружения при изменяющемся выводе. `requirements-test.txt` теперь
включает зависимости модулей и `python-docx`. Проверка в отдельном чистом venv,
без внешнего PYTHONPATH: 141 тест, OK, 2 пропуска; `pip check` также проходит.
Файлы ядра не менялись.

## Инвентаризация интерфейса модулей

`start`, `prepare`, `turn`, `reset`, `stop` ниже обозначают `session_started`,
`prepare_turn`, `turn_completed`, `before_reset`, `session_stopped`. Тесты
используют управляемую модель, если не указано иное. Назначение и дополнительные
внешние зависимости описаны выше; отсутствие настройки не считается ошибкой.

| Модуль | Инструменты; события; управление | Проверка и готовность |
| --- | --- | --- |
| shell | `shell`; делегирует события BasicHost; без своих controls | Песочница и границы — автоматические тесты, локальный bwrap. |
| project_state | `project_init`, `project_update`, `project_review_complete`, `finish`; start, prepare, reset, turn; reset и stop | Тесты State, восстановления журнала и exclusive review. Общей транзакции с ядром нет. |
| project_map | Нет инструментов; start, prepare, stop; без controls | Тесты индекса и модуля, Tree-sitter установлен. |
| images | `view_image`; start; наблюдения в Outcome | Тесты реального файла и контракта наблюдений; vision-модель не проверялась. |
| processes | `process_start/status/logs/stop`; start, stop | Тест реального процесса и очистки; сеть включается настройкой `allow_network`. |
| gui | `gui_start`, `view_gui`, мышь, клавиатура, `gui_close`; start, stop | Тест реального приватного дисплея; Xvfb/X11 необходимы, `allow_network` по умолчанию false. |
| browser | `browser_diagnostics`, при разрешении `browser_evaluate`; start, stop | Тест конфигурации и разрешений; реальный браузер в текущем прогоне не проверялся. Без `config` пассивен. |
| expert | `ask_expert`; start, stop | Тесты с управляемым endpoint; для настоящего нужны `base_url`, `model` и разрешение сети при необходимости. |
| office | `docx_*`, `xlsx_*`: inspect/read/edit/render; start, stop | Чтение и изменение реальных файлов в тестах; внешний рендер отдельно зависит от LibreOffice/Poppler. |
| gpu_shell | `shell_released`; start; политика release_model | Контролируемая выгрузка/восстановление в тестах; реальная модель не проверялась. Review/reset не принудительны. |
| reasoning_code | `write_code_from_reasoning`; start, prepare, turn, stop | Тест записи в реальной песочнице и срока жизни ссылок; контекст текущего ответа предоставляется ядром. |
| loop_detection | Нет инструментов; start, prepare, reasoning_fragment, turn, reset; interrupt и stop | Тесты повторов и циклов; семантическая полнота не гарантируется. `max_interruptions` настраивается. |
| interactive | `ask_user`; start, key_pressed, paused; pause | Тесты паузы, PTY и многострочного ввода; только при настроенном терминале работает ввод в процессе. |
