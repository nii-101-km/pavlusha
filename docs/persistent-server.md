# Повторное использование llama-server

Для нескольких последовательных запусков обычной модульной сборки можно оставить локальный llama-server работать между задачами:

```sh
python3 project_state_agent.py --config /path/to/assembly.json \
  --workdir /path/to/work --session-dir /path/to/session-1 \
  --keep-server -- 'Первое задание'

python3 project_state_agent.py --config /path/to/assembly.json \
  --workdir /path/to/work --session-dir /path/to/session-2 \
  --keep-server -- 'Второе задание'

python3 stop_server.py
```

`--keep-server` работает с локальным backend `llama-cpp`. В конфигурации требуется `runtime.llama_server` или `llama_server_config`: адреса самого по себе недостаточно, чтобы запустить сервер или сравнить настройки. Для новой задачи используйте новую директорию технической сессии.

Первый запуск при свободном адресе поднимает сервер и оставляет его работать после завершения Павлуши. Следующий запуск сверяет сохранённые параметры адаптера и выбранную модель, проверяет состояние сервера и использует тот же процесс. Если параметры изменились, Павлуша сообщает об ошибке и не останавливает сервер. Постоянный процесс адаптера для этого не запускается.

Если по адресу уже работает сервер, запущенный не в этом режиме, полностью проверить его параметры запуска через API нельзя. Поэтому `--keep-server` откажется его использовать и не будет его останавливать. Для обычного подключения к внешнему серверу используйте конфигурацию без запуска управляемого `llama_server` и без `--keep-server`.

Без `--keep-server` действует прежний режим: сервер, запущенный этой сессией, завершается при её выходе, включая обработанное закрытие терминала. Внешний сервер, к которому Павлуша только подключилась, не останавливается. Отдельный минимальный запуск `agent.py` этот флаг пока не поддерживает.

## Остановка

`python3 stop_server.py` останавливает зарегистрированный сервер Павлуши, сверяя данные процесса, и очищает принадлежащий ему временный каталог KV. Для безопасной идентификации процесса требуется Linux с поддержкой pidfd. Если серверов зарегистрировано несколько, укажите адрес:

```sh
python3 stop_server.py --base-url http://127.0.0.1:8899/v1
```

Одновременные сессии с `--keep-server` для одного адреса запрещены, как и остановка сервера во время такой сессии. После её завершения остановку можно повторить. При некорректном состоянии или несовпадении идентичности процесс не останавливается по догадке.

Служебные данные и журнал сервера находятся в приватном `~/.local/state/pavlusha/servers`; для изолированной среды каталог можно указать в переменной `PAVLUSHA_SERVER_STATE_DIR`. Доступ к этому каталогу должен оставаться только у владельца. KV по настройке `kv_storage: "ram"` остаётся в `/dev/shm`, пока сервер не остановлен. Если сервер завершился вне Павлуши или компьютер был выключен аварийно, запись может устареть; `stop_server.py` не сигнализирует процессу с другой идентичностью.

Этот режим оставляет сервер запущенным намеренно, в том числе после завершения последней сессии. Чтобы освободить GPU, вызовите `stop_server.py`.
